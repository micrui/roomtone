## Why the first live runs did not lock (and then did)

With the M8 speaker silent the marker was found every block (PSR 14-31 dB) but echo
suppression sat at 2.7 dB. Offline experiments through the same speakers and mic settled it:

| Playback | Echo suppression |
|---|---|
| 1-4 kHz noise, same signal on both speakers | 25 dB |
| the M8 drone as the M8 sent it (stereo) | 1.9 dB |
| the same M8 drone folded to mono | 19.6 dB |
| the M8's left channel on both speakers | 22 dB |

The M8's left and right are nearly uncorrelated (correlation 0.05; the side signal is as
loud as the mid), so the two laptop speakers played different signals and one response
could not model both. The mixer now folds the M8 to mono (`Config.mono_output`). With that
the live run reached 23-24 dB in every block from the second on, residual -40 dBFS against
-22 dBFS raw, no glitches.

It still did not reach "locked" in 6 blocks, for two reasons visible in the session log:
the single-marker drift estimate in block 0 read 10.7 ppm where the aggregate's true drift
is about 0.2 ppm (so block 0 was smeared and block 1's marker sat 14 samples off the
prediction), and the response-stability check compared responses in the 4-10 kHz marker
band, where the half-sample delay jitter between blocks already reads as a different room
(change 0.5-1.8 against a 0.3 threshold). Fixes: a Theil-Sen slope with a significance
test for the single-marker drift, and a comparison that lets one response slide up to
2 samples before measuring the distance.

## Fixed along the way

- `roomtone baseline` never found its own marker: it emits an 8 s, -15 dB burst but the
  Locker was never told, so it regenerated the default 4 s sequence. The baseline loop now
  aligns blocks to bursts and passes the emitted parameters, as the Engine does.
- A baseline that never locked was still saved, as an array of `None`, and crashed
  `roomtone run --baseline` at load. Saving now refuses, and loading validates the file.

## Still open on this rig

- The mood read "conversation" during the drone with nobody talking: the residual at
  -36 to -40 dBFS still carries some music, and the voice feature climbed on it. Needs
  a look at the features once the lock is stable.
- The marker and the music both leave through the laptop speakers at the system volume;
  the music is whatever the M8 plays, so without Tidal the drone script is the only source.
- PortAudio's default "high" latency adds about 250 ms to the path. Harmless for the lock
  (it searches up to 3 s) but worth passing `latency="low"` in `SoundDeviceBackend` if the
  TUI's delay figure should match the acoustic path.

## Audition: the score on the M8, 2026-10-10 evening

SuperCollider 3.14, SuperDirt and Tidal 1.10 were installed on the laptop and the Tidal
file evaluated clean on the first try (`roomtone tidal`). `roomtone run --audition
empty:60,cooking:120,dinner:90,party:120 --block-seconds 10` drove the Controller through
the four states while a MIDI tap logged what Tidal sent and the M8's USB output was recorded.

What Tidal sent (notes per minute per layer; held = median note length):

| Phase | drone | pad | figure | phrases | shimmer | pulse | bass |
|---|---|---|---|---|---|---|---|
| empty | 3.0, held 17.4 s | | | | | | |
| cooking | 3.5 | 2.5, held 20.2 s | 3.5 | 1.5 | 6.0 | 8.0 | |
| dinner | 3.3 | 2.7 | 6.0 (ducked) | | 11.3 | 6.7 | |
| party | 3.5 | 3.0 | | | 11.5 | 24.5 | 0.5, held 34 s |

At least one held note is sounding 88% of the time in "empty" and 100% of the time in
every other state, and every note was in the scale and key in force (allowing for the one-block
delay before a new mood reaches Tidal and the transpose that stepped in at block 40). The
mood CCs all moved as written (CC 20 tempo 16 to 56, cutoffs, volumes, sends, EQ).

What the M8 made of it: mostly silence. 60 to 100% of every block sat under -50 dBFS even
with six layers on, because every instrument in the loaded song decays within seconds of
its note-on; a held 17 s drone note is gone in about 10 s. That is the instruments'
envelopes, not the score (m8/SETUP.md section 3 now says which layers need ADSR sustain).
Also seen: the M8 peaks at 0.98 on a single note, so its main level needs setting; and a
restart of the MIDI path mid-run dropped note-offs, after which tracks 1 to 7 ignored new
notes until an all-notes-off (`roomtone panic`).

Changes from this: key drift moves by fifths (never a semitone or a minor third), the
conversation scale is dorian rather than natural minor so fewer notes clash while old held
notes ring on, `roomtone panic`, and panic on `roomtone tidal` exit.
